# Корт

Уйгурская карточная игра: двое на двое, 52 карты, по 13 на руки, первая команда с 7 взятками берёт раздачу.

Можно играть одному с тремя ботами или с друзьями по ссылке — свободные места занимают боты. Играть можно гостем; вход через Google добавляет историю партий, свой аватар, открытые комнаты и просмотр чужих игр.

> Правила пока черновые. Что реализовано и какие вопросы открыты — в [docs/RULES.md](docs/RULES.md).
> План проекта — в [закреплённой задаче](https://github.com/rasult22/cort/issues/9).

## Запуск

Нужны Node 20+ и pnpm.

```sh
pnpm install
pnpm dev          # клиент: http://localhost:5173 — игры с ботами уже достаточно
pnpm dev:server   # сервер для игры с друзьями: http://localhost:8787
```

Серверу для запуска ничего не нужно: без настроек все играют гостями, а данные лежат в папке `apps/server/.data`. Настройки — в `apps/server/.env` (в git не попадает), что в него писать — в [`apps/server/.env.example`](apps/server/.env.example).

Чтобы позвать друзей в той же сети, откройте клиент по адресу компьютера (`http://192.168.x.x:5173`) и отправьте ссылку из лобби.

Один процесс на всё (для выкладки):

```sh
pnpm build          # собирает клиент в apps/web/dist
pnpm start:server   # отдаёт клиент и принимает игроков на порту PORT (по умолчанию 8787)
```

## Аккаунты и гости

Вход — через Google: браузер получает от Google подписанный токен, сервер проверяет подпись и то, что токен выдан именно нашему приложению, и открывает свою сессию (cookie `cort_session`, недоступная скриптам). Секрет клиента Google не нужен. Чтобы вход заработал, серверу нужна переменная `GOOGLE_CLIENT_ID`; без неё кнопки входа нет.

| | Гость | С аккаунтом |
|---|---|---|
| Игра с ботами, комната по ссылке или коду, место в открытой комнате | да | да |
| Эмодзи, стикеры, мемы | да | да |
| Создать открытую комнату (видна всем в списке) | — | да |
| Смотреть чужую игру | — | да |
| Имя и аватар из профиля (фото Google или картинка на выбор) | — | да |
| История партий и статистика | — | да |

Ограничения проверяет сервер, а не только интерфейс. Партии, сыгранные гостем, записываются на его устройство и переезжают в аккаунт, когда с этого устройства входят. Аккаунт удаляется из профиля; у других игроков партии с ним остаются, но без имени.

Для разработки есть вход без Google — `DEV_LOGIN=1` (в продакшене не работает).

## Мобильное приложение

`apps/mobile` — приложение на Expo (SDK 58) с Reanimated. Пока в нём игра с ботами; правила, боты и логика стола — те же пакеты, что у веба.

```sh
pnpm dev:mobile   # запускает Metro; дальше — Expo Go на телефоне (QR-код) или эмулятор
```

На Android-эмуляторе: поставьте Expo Go, пробросьте порт и откройте приложение:

```sh
adb reverse tcp:8081 tcp:8081
adb shell am start -a android.intent.action.VIEW -d exp://127.0.0.1:8081 host.exp.exponent
```

Сквозной тест — [Maestro](https://maestro.dev) проходит целую раздачу на эмуляторе или телефоне (Metro должен быть запущен):

```sh
pnpm test:mobile
```

## Выкладка

Игра выкладывается одним сервисом: сервер сам раздаёт собранный клиент. В репозитории лежат `Dockerfile` и `railway.json`, так что на Railway настраивать нечего.

Один раз:

1. В Railway: **New Project → Deploy from GitHub repo** → выбрать этот репозиторий, ветка `main`.
2. В сервисе: **Settings → Networking → Generate Domain**.
3. По желанию: **Settings → Deploy → Wait for CI** — тогда выкладка идёт только после зелёных проверок.

Чтобы работали вход и история:

4. В проекте Railway: **New → Database → PostgreSQL**. В сервисе игры: **Variables** → `DATABASE_URL` = `${{Postgres.DATABASE_URL}}`.
5. Там же: `GOOGLE_CLIENT_ID` — идентификатор клиента OAuth типа «Web application» из Google Cloud Console. В его **Authorized JavaScript origins** должен быть адрес сайта; redirect URI не нужны.

Таблицы сервер создаёт и обновляет сам при запуске (миграции лежат в `apps/server/drizzle`).

Дальше пуш в `main` выкладывается сам — но только если он меняет сервер, веб-клиент, общие пакеты или настройки сборки (список в `watchPatterns` в `railway.json`). Изменения только в мобилке, документации или инструментах прод не трогают. `pnpm-lock.yaml` в списке нет намеренно: смена зависимостей сервера или веба всегда меняет и их `package.json`. Порт Railway передаёт через `PORT`, проверка живости — `/health`.

Образ собирает только сервер и веб-клиент: зависимости мобилки в него не попадают.

Идущие партии переживают выкладку: каждый стол после каждого хода сохраняется в базу, новый процесс поднимает столы и ждёт игроков — клиенты переподключаются сами и возвращаются на свои места. Пока за столом никого нет, игра стоит на паузе. Без `DATABASE_URL` данные лежат в файлах контейнера и с выкладкой пропадают — и столы, и аккаунты.

## Проверки

```sh
pnpm test        # правила, боты, сервер, модель стола
pnpm typecheck   # все пакеты, включая мобилку
```

Проверка глазами в настоящем браузере (нужен Edge или Chrome и запущенные `pnpm dev` / `pnpm dev:server`):

```sh
node tools/screenshot.mjs shots     # раздача с ботами на десктопе и телефоне
node tools/online-check.mjs shots   # три браузера за одним столом: хозяин с аккаунтом, гость и зритель
```

Второй проверке нужен сервер в тестовом режиме — со входом без Google, быстрыми ботами и коротким таймером, иначе целая партия займёт минут десять:

```sh
DEV_LOGIN=1 FAST_BOTS=1 TURN_SECONDS=8 pnpm dev:server
```

После изменения `apps/server/src/db/schema.ts` новая миграция пишется командой `pnpm --filter @cort/server db:generate`.

## Как устроено

```
packages/engine    правила игры — без интерфейса, сети и случайности извне
packages/protocol  сообщения между клиентом и сервером
packages/client    общее для клиентов: сессии, модель стола, раскладка
apps/web           веб-клиент: React, анимации на Motion, звук на WebAudio
apps/mobile        мобильное приложение: Expo, Reanimated, react-native-svg
apps/server        сервер: столы, зрители, аккаунты, история (Node, Fastify, ws, Postgres через Drizzle)
tools              проверка игры в браузере, конвертация звуков
docs/RULES.md      спецификация правил и открытые вопросы
```

**Движок** — это чистая функция `apply(state, action) → { state, events }`.

- Состояние — обычный объект: его можно сохранить, переслать и воспроизвести. Тасовка идёт от сида.
- `viewFor(state, seat)` отрезает всё, что игрок видеть не должен. По сети уходит только это.
- `events` описывают, что произошло (карта сыграна, взятка взята). По ним клиент рисует анимации и играет звуки.
- Спорные правила собраны в `Rules` (`packages/engine/src/types.ts`): поменять ответ — значит поменять настройку.
- `viewForSpectator(state)` — то же для зрителя: стол и счёт без чьих-либо карт.
- `GameRunner` ведёт стол: ходит за ботов и раздаёт следующую раздачу. Его используют и офлайн-игра, и сервер, поэтому ведут они себя одинаково. Он же следит за временем на ход: не успел — ход делается за игрока.

**Звук** — записи настоящих карт (набор Kenney, CC0) плюс смоделированная щипковая струна для мелодий; всё в `apps/web/src/sound.ts`.

**Клиенты** не знают, с кем говорят. Экран игры работает с интерфейсом `Session` (`packages/client`); у него две реализации — `LocalSession` (всё на устройстве) и `RemoteSession` (WebSocket, пока только в вебе).

**Модель стола** — `TableStore` в `packages/client`: решает, что показывать прямо сейчас (держит взятую взятку на столе, показывает козырь, ждёт перед итогами) и какие звуки играть. Она без React: веб и мобилка читают её через `useSyncExternalStore`, а звук и вибрацию каждая платформа подставляет свои.

**Ключевые моменты** — `MomentTracker` там же: по событиям движка замечает козырь по тузу, козырь на козырь, спасённую напарником взятку, «последний шанс» при шести взятках, решающую взятку, камбэк и сухую победу. Момент — это событие с типом и участниками; как его показать, решает клиент. За обновление показывается один, самый редкий: вспышка на каждой взятке ничего бы не значила.

**Сервер** хранит единственную полную копию состояния. Место игрока определяет сервер, а не сообщение клиента. Если игрок отвалился, за него ходит бот; по возвращении он получает своё место обратно. Зрителю уходит только вид без карт. Сыгранная до конца партия записывается целиком: состав, счёт по раздачам, козыри, сид и все ходы — по сиду и ходам её можно воспроизвести.

Без `DATABASE_URL` сервер хранит данные в PGlite — это Postgres, собранный для запуска внутри процесса. SQL один и тот же, поэтому для разработки и тестов ставить ничего не нужно.

Полезные параметры адреса при разработке: `?seed=7` — одна и та же раздача, `?demo` — за вас тоже играет бот.
